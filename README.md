# ShredingerBox Mobile

Мобильный VPN-клиент на ядре [sing-box](https://github.com/SagerNet/sing-box) — Android первым,
позже iOS. Младший брат десктопного [ShredingerBox](https://github.com/ThisIsSuigetsu/shredingerbox):
добавил подписку, нажал одну кнопку — подключено.

> Статус: Android — подписки и ключи, пинг, правила для приложений и сайтов, режимы TUN и «Прокси», расход трафика, плитка в шторке, автозапуск, обновление из приложения.

## Стек

- **[Tauri 2](https://v2.tauri.app/) (mobile)** — оболочка приложения.
- **Интерфейс** — TypeScript + CSS без фреймворков, тёмная тема в стиле десктопа.
- **Rust** — разбор ключей и подписок, сборка конфига sing-box, правила и готовые наборы.
  Переносится из десктопного клиента (`links.rs`, `config.rs`, `presets.rs`).
- **sing-box как библиотека `libbox`** — собирается `gomobile` из исходников sing-box в `.aar`
  (на iOS — `.xcframework`). Запускать ядро отдельным exe, как на десктопе, на телефоне нельзя.
- **Kotlin-плагин Tauri** с `VpnService`: поднимает TUN-интерфейс и отдаёт его файловый
  дескриптор в libbox.
- **iOS (позже)** — Swift Network Extension (`NEPacketTunnelProvider`) с тем же libbox.
  Нужен платный аккаунт Apple Developer.

Почему не нативный Kotlin/Compose: пришлось бы заново писать интерфейс и всю логику ключей и
конфига на Kotlin, а потом ещё раз на Swift для iOS. С Tauri общая часть одна на все платформы,
а платформенным остаётся только сам VPN-сервис.

## План

### Этап 1 — MVP (Android)
- [x] Добавить подписку по ссылке или отдельный ключ (`vless://`, `hy2://`, `trojan://`, `ss://`).
- [x] Список серверов, сгруппированный по подпискам.
- [x] Подключение через `VpnService` + libbox, уведомление с кнопкой «Отключить».
- [x] Пинг серверов и переключение без переподключения.
- [x] Режим «Прокси» без VPN: локальный прокси `127.0.0.1:2080`.
- [x] Плитка в шторке быстрых настроек.
- [x] Подключение при включении телефона и поддержка «Постоянной VPN» (Always-on).
- [x] Добавление по ссылке `shredingerbox://add?url=…` и по QR-коду.

### Этап 2 — правила
- [x] Приложения через VPN или напрямую — по имени пакета, выбор из списка установленных.
- [x] Сайты через VPN или напрямую.
- [x] Готовые наборы сайтов (как на десктопе).
- [x] Расход трафика за месяц по серверам и скорость.

### Этап 3 — сборка и обновления
- [x] Сборка подписанного APK в GitHub Actions (вместе со сборкой libbox).
- [x] Своё обновление: проверить релиз на GitHub, скачать APK и открыть установщик.

### Этап 4 — iOS (отложен)
Пока клиент для своих, iOS не делаем: для VPN на iPhone нужен платный аккаунт Apple Developer
(бесплатный Apple ID не даёт Network Extension), а для App Store — ещё и юрлицо. На iPhone
подписка работает в готовых клиентах на sing-box и Xray.

- [ ] Network Extension с libbox, тот же интерфейс и Rust-логика.
- [ ] Раздача через TestFlight или Ad Hoc (AltStore с бесплатной подписью VPN не поднимет).

## Что нужно для сборки

- Android Studio (Android SDK, платформа API 35+, Build-Tools, NDK, встроенная JBR 21).
- Rust с таргетами `aarch64-linux-android`, `armv7-linux-androideabi`, `x86_64-linux-android`,
  `i686-linux-android`.
- Node.js и npm.
- Go и `gomobile` — для сборки libbox.

На Windows ещё нужен включённый **режим разработчика** (Параметры → Система → Для
разработчиков): Tauri кладёт собранную библиотеку в Android-проект символической ссылкой.

Отладочный APK для телефонов на arm64:

```bash
npm install
ARCHS=arm64 scripts/build-libbox.sh   # ядро sing-box → src-tauri/gen/android/app/libs/libbox.aar
npx tauri android build --debug --apk --target aarch64
```

`scripts/build-libbox.sh` скачивает исходники sing-box нужной версии в `build/`, ставит
`gomobile` и собирает библиотеку только с теми протоколами, что умеет клиент. Без `ARCHS`
собираются все четыре архитектуры — так нужно для релиза. На Windows скрипт запускается из Git Bash.

Запуск на подключённом телефоне с перезагрузкой интерфейса на лету: `npx tauri android dev`.

## Выпуск версии

Релиз собирает GitHub Actions (`.github/workflows/release.yml`) по метке `v*`: ядро, подписанный
APK для arm64 и релиз с ним. Установленное приложение само находит новый релиз и предлагает обновиться.

1. Поднять версию в `package.json`, `src-tauri/tauri.conf.json` и `src-tauri/Cargo.toml`.
2. Закоммитить, поставить метку и отправить: `git tag v0.2.0 && git push && git push --tags`.

Подпись: ключ один навсегда — APK с другим ключом Android не поставит поверх установленного.
Ключ хранится в секретах репозитория `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Его копию стоит держать вне репозитория — без неё
следующую версию не выпустить. Отладочные сборки подписаны другим ключом, поэтому поверх них
релиз не встанет: отладочную версию нужно один раз удалить.
