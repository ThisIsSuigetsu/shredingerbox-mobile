# ShredingerBox Mobile

VPN-клиент для Android на ядре [sing-box](https://github.com/SagerNet/sing-box). Младший брат
десктопного [ShredingerBox](https://github.com/ThisIsSuigetsu/shredingerbox): добавил подписку,
нажал одну кнопку — подключено.

**[Скачать последнюю версию](https://github.com/ThisIsSuigetsu/shredingerbox-mobile/releases/latest)** ·
[История версий](CHANGELOG.md)

## Установка

1. Скачайте файл `ShredingerBox-….apk` со [страницы релиза](https://github.com/ThisIsSuigetsu/shredingerbox-mobile/releases/latest)
   на телефон.
2. Откройте его. Android спросит, можно ли устанавливать приложения из браузера или «Файлов», — разрешите.
3. Откройте ShredingerBox и добавьте подписку или ключ, которые вам прислали.
4. Нажмите большую кнопку. В первый раз Android попросит разрешить VPN.

Дальше приложение обновляется само: когда выходит новая версия, оно предлагает её скачать и
показывает, что изменилось.

Нужен Android 7 или новее на 64-битном ARM — так устроены почти все телефоны последних лет.

## Что умеет

- **Подписки и ключи** `vless://`, `hy2://`, `trojan://`, `ss://`: вставить, отсканировать QR-код,
  открыть ссылку `shredingerbox://add?url=…` или просто скопировать — приложение предложит добавить само.
- **Пинг серверов.** Пока VPN включён, задержка меряется через туннель, а сервер переключается
  мгновенно, без переподключения.
- **Правила**, как на десктопе: приложения и сайты через VPN или напрямую, готовые наборы
  (YouTube, Discord, Instagram и другие). Приложения «напрямую» вообще не видят VPN — удобно для банков.
- **Два режима:** TUN — VPN для всего телефона, и «Прокси» — без VPN, локальный прокси
  `127.0.0.1:2080` для приложений, где он указан.
- **Расход трафика** по каждому серверу за месяц и скорость на главной.
- **Плитка в шторке**, подключение при включении телефона и «Постоянная VPN» (Always-on).
- VPN работает дальше, даже если закрыть приложение.
- **Журнал ядра** с копированием — пригодится, если что-то не работает.

На iPhone своего клиента пока нет — см. [этап 4](#этап-4--ios-отложен). Подписка работает в готовых
клиентах на sing-box и Xray.

## Как устроено

- **[Tauri 2](https://v2.tauri.app/) (mobile)** — оболочка приложения.
- **Интерфейс** — TypeScript + CSS без фреймворков, тёмная тема в стиле десктопа.
- **Rust** — разбор ключей и подписок, сборка конфига sing-box, правила и готовые наборы, пинг,
  счётчик трафика, обновления. Часть перенесена из десктопного клиента (`links.rs`, `presets.rs`).
- **sing-box как библиотека `libbox`** — собирается `gomobile` из исходников sing-box в `.aar`.
  Запускать ядро отдельным exe, как на десктопе, на телефоне нельзя.
- **Kotlin** — `VpnService` с libbox, плитка в шторке и автозапуск. Они живут в отдельном процессе
  `:vpn`, чтобы VPN не закрывался вместе с окном.

Почему не нативный Kotlin/Compose: пришлось бы заново писать интерфейс и всю логику ключей и
конфига на Kotlin, а потом ещё раз на Swift для iOS. С Tauri общая часть одна на все платформы,
а платформенным остаётся только сам VPN-сервис.

## Сборка

Нужны:

- Android Studio (Android SDK, платформа API 35+, Build-Tools, NDK, встроенная JBR 21).
- Rust с таргетами `aarch64-linux-android`, `armv7-linux-androideabi`, `x86_64-linux-android`,
  `i686-linux-android`.
- Node.js и npm.
- Go и `gomobile` — для сборки libbox.

На Windows ещё нужен включённый **режим разработчика** (Параметры → Система → Для
разработчиков): Tauri кладёт собранную библиотеку в Android-проект символической ссылкой.

Отладочный APK для телефонов на arm64:

```bash
npm install
ARCHS=arm64 scripts/build-libbox.sh   # ядро sing-box → src-tauri/gen/android/app/libs/libbox.aar
npx tauri android build --debug --apk --target aarch64
```

`scripts/build-libbox.sh` скачивает исходники sing-box нужной версии в `build/`, ставит
`gomobile` и собирает библиотеку только с теми протоколами, что умеет клиент. Без `ARCHS`
собираются все четыре архитектуры. На Windows скрипт запускается из Git Bash.

Посмотреть интерфейс без телефона: `npm run dev` и открыть `http://localhost:1420` — вместо Tauri
подставляются демо-данные. Запуск на подключённом телефоне с перезагрузкой интерфейса на лету:
`npx tauri android dev`.

## Выпуск версии

Релиз собирает GitHub Actions (`.github/workflows/release.yml`) по метке `v*`: ядро, подписанный
APK для arm64 и релиз с ним. Описание релиза берётся из раздела этой версии в
[CHANGELOG.md](CHANGELOG.md) — его же приложение показывает в окне обновления.

1. Дописать в `CHANGELOG.md` раздел `## X.Y.Z` — что изменилось, простыми словами.
2. Поднять версию в `package.json`, `src-tauri/tauri.conf.json` и `src-tauri/Cargo.toml`.
3. Закоммитить, поставить метку `vX.Y.Z` и отправить коммит и метку.

Сборка проверяет, что версия в метке совпадает с `package.json` и что в `CHANGELOG.md` есть её раздел.

Подпись: ключ один навсегда — APK с другим ключом Android не поставит поверх установленного.
Ключ хранится в секретах репозитория `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Его копию стоит держать вне репозитория — без неё
следующую версию не выпустить. Отладочные сборки подписаны другим ключом, поэтому поверх них
релиз не встанет: отладочную версию нужно один раз удалить.
